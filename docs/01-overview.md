# 何を、どういう判断で作ったか

## 解こうとした問題

**領収書を出してメールで送る。** それだけです。

小さな会社でこれをやると、だいたいこうなります。Excelで作って、PDFに書き出して、
メールに添付して送る。宛名を間違えたら作り直し。誰にいつ何を送ったかは、送信済みフォルダ頼み。

ここを、フォームに4つ入れたら終わる形にしました。

## 最初に決めたこと

### PDFはメールに添付しない

これが一番大きい判断です。

添付にすると、**宛先を1文字間違えた瞬間に、領収書が他人の手元に残ります。**
取り消せません。相手の受信箱にあるものは消せないからです。

なので、PDFは添付せず、こういう形にしました。

```
メール本文にURL（32桁のランダムな文字列）
   ↓ 開く
メールアドレスの入力を求められる
   ↓ 一致
PDFがダウンロードされる
```

URLだけが漏れても開けません。宛先を間違えても、その人のアドレスとは一致しないので開けません。
**2つ揃わないと開かない**ようにしてあります。

### 認証前は何も見せない

ダウンロードページは、メールアドレスを入れるまで**顧客名も金額も領収書番号も出しません。**

URLが漏れたとき、「誰宛のいくらの領収書か」が分かるだけでも情報漏洩です。
だから、認証前の画面は「領収書のダウンロード」としか書いていません。

エラーメッセージも「そのアドレスは登録されていません」とは言いません。
それは総当たりする側にとって手がかりになるからです。

### データベースを使わない

顧客名・金額・メールアドレスをJSONファイルに書いています。`flock` で排他制御します。

理由は**設置できる場所を増やすため**です。日本の小さな会社が持っているのは、
たいていPHPが動く共有レンタルサーバーです。MySQLの設定から始めると、そこで止まります。

代わりに、台帳ファイルは `.htaccess` でWebから直接読めないようにしてあります。

### 外部ライブラリを使わない

PDF生成に TCPDF や mPDF を使っていません。Composer も使いません。

共有サーバーには Composer が無いことが多く、あっても数十MBの `vendor/` を
FTPで上げるのは現実的ではないからです。

そのかわり、PDFの仕様を直接書いています。日本語は Adobe-Japan1 の
CIDフォントを参照する形にして、**フォントファイル自体は埋め込んでいません**。
これが共有サーバーで日本語PDFを出す一番軽い方法です。

## 領収書としての体裁

日本の領収書に必要なものを調べて入れました。

| 項目 | 扱い |
|---|---|
| 宛名 | 必須。「様」は自動 |
| 金額（税込） | 必須。主役なので大きく |
| 但し書き | 空欄なら「お品代」 |
| 発行日 | 必須 |
| 発行者 | 設定から |
| 税率ごとの内訳 | 10% / 8% / 対象外 |
| 適格請求書発行事業者の登録番号 | **設定したときだけ印字** |
| 収入印紙 | **電子交付なので不要**である旨を明記 |
| 住所 | **法定の記載事項ではない。**不要なら設定しない |

住所が必須でないのは意外に思われるかもしれませんが、適格請求書の記載事項に住所は含まれていません。
登録番号があれば国税庁の公表サイトで事業者を特定できるためです。

**登録番号を設定していないときは、架空の番号を入れずに「記載しておりません」と印字します。**
無いものを有るように見せない、という判断です。

## 金額の計算

領収書は税込の総額を書きます。なので**入力も税込**にしました。

内訳を出すときに気をつけたのは、**合計が必ず税込総額に一致すること**です。

```
9,999円（10%）→ 税抜 9,090 ＋ 消費税 909 ＝ 9,999  ✓
```

税抜を切り捨て、差額を消費税に寄せています。ここで1円ズレると、
経理で突き合わせたときに合わなくなり、領収書として使えません。

テストで固定してあります（`scripts/check_kinvoice.php`）。

## 全体の大きさ

| ファイル | 行数のめやす | 中身 |
|---|---|---|
| `kinvoice.php` | 約390 | 管理画面 |
| `kinvoice_dl.php` | 約135 | ダウンロードページ |
| `kinvoice_auth.php` | 約160 | ログイン |
| `kinvoice_lib.php` | 約270 | 台帳・税計算・メール |
| `kinvoice_pdf.php` | 約225 | PDF生成 |

**合わせて約1,180行です。**全部読めます。

読めるサイズであることは、教材として意図した性質です。
これ以上減らすと本番の関心事（認証・排他制御・CSRF・レート制限）が抜け落ちますし、
これ以上増やすと最後まで読めなくなります。
