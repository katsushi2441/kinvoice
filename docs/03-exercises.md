# 改造の練習

読むだけでは身につきません。**手を動かして、自分で結果を確かめてください。**

やり方は同じです。AIエージェント（Claude Code、Codex など）にこのフォルダを渡して、
課題を伝えます。ただし**AIが「できました」と言っても、確認するまで信じないでください。**
確認方法を各課題に書いてあります。

---

## 練習1: 但し書きの選択肢を用意する（やさしい）

毎回手で打つのは面倒です。よく使う但し書きを選べるようにしてみましょう。

**AIへの頼み方の例**

> `kinvoice.php` の但し書きの入力欄に、よく使う候補を選べるようにしてください。
> 候補は「お品代」「システム開発費」「コンサルティング料」「保守費」。
> 選んでも、自分で自由に打てる状態は残してください。

**確認**
- [ ] 候補から選べる
- [ ] 候補にない文字も打てる
- [ ] 空欄のまま発行すると、PDFに「お品代」と出る

**つまずきやすいところ**: `<select>` にすると自由入力ができなくなります。
`<input list="...">` と `<datalist>` を使うと両立します。

---

## 練習2: 「請求書」を出せるようにする（ふつう）

領収書は「もらった」証明、請求書は「これから払ってください」という書類です。
違いは、実はそれほど多くありません。

必要な変更：

| 領収書 | 請求書 |
|---|---|
| 「上記正に領収いたしました」 | 「下記のとおりご請求申し上げます」 |
| — | **お支払期限**が要る |
| — | **振込先**が要る |
| 収入印紙は不要（電子交付） | そもそも印紙の対象外 |

**AIへの頼み方の例**

> 領収書と同じ仕組みで、請求書も出せるようにしてください。
> 発行画面で「領収書 / 請求書」を選べるようにして、請求書のときは
> お支払期限（発行日から30日後を初期値）と振込先を印字してください。
> 振込先は設定ファイル（`kinvoice_config.php`）から読んでください。

**確認**
- [ ] 領収書がこれまでどおり出る（**壊していないこと**）
- [ ] 請求書に支払期限と振込先が出る
- [ ] 振込先を設定していないときは、その欄が出ない（空欄の枠が残らない）
- [ ] `php scripts/check_kinvoice.php` が全部通る

**つまずきやすいところ**: 既存のテストを壊しがちです。新しい機能を足したら、
**必ず既存のテストを流してください。**「動いた」と「壊していない」は別です。

## 練習3: 送信履歴をCSVで書き出す（ふつう）

経理に渡すために、発行した領収書の一覧をCSVにします。

**AIへの頼み方の例**

> 管理画面の送信履歴に「CSVで書き出す」ボタンを付けてください。
> 列は 領収書番号・発行日・宛名・税込金額・消費税額・但し書き・送信先メール・ダウンロード回数。
> Excelで開いて文字化けしないようにしてください。

**確認**
- [ ] ダウンロードできる
- [ ] **Excelで開いて日本語が化けない**
- [ ] 金額がカンマ区切りではなく数値として入っている（計算できる）
- [ ] **ログインしていない状態でURLを直接叩いても落ちてこない**

**つまずきやすいところ**: 3つあります。

1. Excelは UTF-8 のCSVを化けさせます。BOMを付けるか Shift_JIS にする必要があります
2. 金額を `1,000` と書くとExcelが文字列として扱い、合計が出せません
3. **認可を忘れがちです。**CSVには顧客名とメールアドレスが入ります。
   ログイン確認を入れないと、URLを知っている人は誰でも落とせます

3つめは、AIが最も忘れる部分です。**必ず自分でログアウトして試してください。**

## 練習4: まっさらな場所に設置してみる（大事）

これは機能追加ではありませんが、**一番学べます。**

`public/` の中身を、設定ファイルを**含めずに**別の場所へコピーして、
`INSTALL.md` の手順どおりに一から設置してみてください。

**確認**
- [ ] 設定が無い状態で「初期設定が終わっていません」と出る
- [ ] 設定を置くと、自分の会社名がヘッダーに出る
- [ ] 発行したPDFに、**他人の会社の情報が一切入っていない**
- [ ] 台帳が `403` で外から読めない

**なぜ大事か**

自分の環境でしか試していないと、**「動く」と「他人が使える」の差**に気づけません。
このシステムも一度そこで失敗しています（`docs/02-failures.md` の罠3）。

作ったものを人に渡す予定があるなら、この練習は必ずやってください。

## 練習5: 見積書まで広げる（むずかしい）

ここまで来たら、見積書も出せるはずです。ただし考えることが増えます。

- 明細が**複数行**になる（領収書は1件でしたが、見積書は品目が並びます）
- 有効期限が要る
- 小計・消費税・合計を、明細から積み上げて計算する

**先に考えてほしいこと**

いまの台帳は「1件＝1金額」です。明細を複数持つには、データの持ち方を変える必要があります。
**AIに頼む前に、どう持つかを自分で決めてください。**

> 明細を配列で持つ。1行は 品名・数量・単価・税率。
> 合計は明細から計算し、台帳には計算結果も一緒に保存する。

こういう方針を先に決めて渡すと、AIの出力が安定します。
決めずに「見積書も作って」と頼むと、毎回違う構造が出てきて収拾がつかなくなります。

**これが `vwork/WORK_PROTOCOL.md` の言っている「成果物を1つ決めてから始める」です。**

## 共通のルール

どの練習でも、これだけは守ってください。

1. **1つずつやる。**まとめて頼むと、どこが壊れたか分からなくなります
2. **変更する前に、いまのテストを流しておく。**元が通っていたことを確かめてから始めます
3. **AIが「できました」と言っても、自分で見る。**画面を開く、PDFを出す、ログアウトして試す
4. **壊したら戻せるようにしておく。**`git init` してコミットしてから始めるのが一番簡単です

詳しくは `vwork/VERIFICATION.md` を読んでください。
