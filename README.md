# kinvoice — 領収書メール送信システム ＋ VWork 教材パッケージ

**領収書をPDFで発行し、ダウンロードURLをメールで送る**システムです。
同時に、**非エンジニアがバイブコーディングを学ぶための教材**として作られています。

- データベース不要。PHPが動くサーバーがあれば動きます
- 外部ライブラリ不要。Composer も npm も使いません
- 約1,180行。**全部読めるサイズ**です

## AIエージェントに設置してもらう場合

**`AGENTS.md` を読ませてください。** それだけです。

Claude Code や Codex にこのフォルダを渡して「AGENTS.md を読んで設置して」と伝えると、
`INSTALL.md` の手順に沿って設置し、各段階を確認しながら進めます。

## 自分で設置する場合

`INSTALL.md` を上から実行してください。要点だけ先に書くと：

1. `public/` の中身をサーバーに置く
2. `php scripts/make_password_hash.php 'パスワード'` でハッシュを作る
3. `kinvoice_config.php.example` をコピーして `kinvoice_config.php` を作り、値を入れる
4. `kinvoice.php` を開いてログイン

設定が足りないうちは、管理画面が**不足している項目を名指しで表示**します。
設定を置くまで誰もログインできません。

## 教材として読む場合

| 読む順 | ファイル | 中身 |
|---|---|---|
| 1 | `docs/01-overview.md` | 何を、どういう判断で作ったか |
| 2 | **`docs/02-failures.md`** | **実際に踏んだ6つの罠。ここが本体です** |
| 3 | `docs/03-exercises.md` | 請求書・見積書へ改造する練習 |

`docs/02-failures.md` は、このシステムを作った1日で実際に起きた失敗の記録です。
きれいに書き直したものではありません。

> メールが「送信済」なのに届いていない／設定ファイルを置いたのに効かない／
> 動いているのに売り物にならなかった／サーバーの設定を古い版で上書きしかけた／
> 画像が汚い原因が直感と逆だった／数字を読み違えて結論を間違えた

**バイブコーディングで難しいのは、コードを書くことではありません。
「動いたように見えて動いていない」を見抜くことです。**

## VWork フレームワーク

`vwork/` に、AIと仕事を進めるための作法が入っています。このシステムもこの作法で作りました。

| ファイル | 中身 |
|---|---|
| `vwork/WORK_PROTOCOL.md` | 目的・成果物・確認・記録の流れ |
| `vwork/RULES.md` | 禁止事項、確認が必要な操作、秘密情報の扱い |
| `vwork/VERIFICATION.md` | **「できました」と言う前の確認手順** |
| `vwork/SERVERS.md.sample` | 環境・データ・公開先を書き留める雛形 |

`docs/02-failures.md` の6つは、すべて `VERIFICATION.md` を守っていれば
早く気づけたものです。抽象的な作法と、実際の失敗が対応しています。

## 仕組み

```
管理者が発行  →  メールでURLを送る（PDFは添付しない）
                      ↓
              お客様がURLを開く
                      ↓
              メールアドレスを入力
                      ↓
              一致したらPDFがダウンロードされる
```

**PDFをメールに添付しません。** 宛先を1文字間違えた瞬間に、領収書が他人の手元に残るためです。
推測困難なURL（32桁）と宛先メールアドレスの2つが揃わないと開きません。

認証前の画面には、顧客名も金額も領収書番号も出しません。
メールアドレスを10回間違えるとロックし、管理画面から解除します。

## 領収書としての体裁

宛名・金額（税込）・但し書き・発行日・発行元・税率ごとの内訳。
**電子交付のため収入印紙は不要**である旨も印字します。

適格請求書発行事業者の登録番号は、設定したときだけ印字します。
**未取得のまま架空の番号を入れないでください**（未設定なら「記載しておりません」と出ます）。

税額の内訳は、端数が出ても**合計が必ず税込総額に一致**します
（9,999円 → 9,090 ＋ 909）。ここが1円ズレると領収書として使えません。

## 構成

| ファイル | 役割 |
|---|---|
| `public/kinvoice.php` | 管理画面（発行フォーム＋送信履歴一覧） |
| `public/kinvoice_dl.php` | お客様用ダウンロードページ |
| `public/kinvoice_auth.php` | 管理者ログイン（既定はパスワード） |
| `public/kinvoice_lib.php` | 台帳・税計算・メール送信 |
| `public/kinvoice_pdf.php` | 領収書PDF生成 |

台帳は `public/kinvoice_data/receipts.json` に flock 付き。`.htaccess` で直接アクセスを塞ぎます。

## 開発

```bash
php scripts/check_kinvoice.php            # 台帳・認証・税計算・PDF の確認（46項目）
php scripts/make_password_hash.php 'pw'   # 管理パスワードのハッシュを作る
```

### メールが届かないとき

まず **SPF** を疑ってください。共有サーバーから送る場合、送信ドメインのSPFに
そのサーバーが含まれていないと、受信側で捨てられます。
**`mail()` は成功を返すので、送信履歴上は「送信済」に見えます。**

```bash
dig +short TXT example.co.jp | grep spf
```

詳しくは `docs/02-failures.md` の罠1に書いてあります。

### 設定を公開領域の外に置く

`KINV_CONFIG_FILE` を先に定義すれば、設定ファイルの場所を変えられます。

```php
define('KINV_CONFIG_FILE', dirname(__DIR__) . '/kinvoice_config.php');
```

### ログイン方式

既定は**パスワード**です。X(Twitter)のOAuth基盤を別に持っている場合は
`KINV_AUTH` を `'x'` にすると、`auth_common.php` を使う方式に切り替わります。
